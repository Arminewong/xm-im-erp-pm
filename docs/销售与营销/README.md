## 推荐使用顺序

市场内容按 04、08 执行并产生线索；销售按 09 判断和跟进；首次沟通使用 02；演示使用 01 和 05；试用使用 03；报价和交付范围使用 06；客户关注员工 AI 入口时使用 07。

## 统一表达

- 第一层讲客户结果：统一业务数据、直接问经营、减少重复录入。
- 第二层讲员工工作方式：员工继续使用熟悉的 AI，确认回复或动作，业务沉淀到 ERP。
- 第三层再讲连接能力：OpenClaw / 龙虾、WorkBuddy、DeepSeek Harness、豆包、开放 API / MCP 和自建 AI。
- 微信场景中，与 AI 沟通的是企业内部员工；客户不直接操作 ERP。
- 不把平台名称、模型数量、MCP 或技术架构当成普通客户的第一购买理由。

## 事实来源与更新规则

- 演示公司、数据和 AI 期望回答以 `../Demo方案/` 为唯一数字口径。
- 产品定位和阶段目标以 `../商业化上市/` 为准。
- 官网信息架构和文案以 `../官网V2/` 与线上已发布页面为准。
- 套餐价格、试用政策和服务范围发生变化时，必须同步官网、PPT、话术和报价说明。
- 任何真实客户名称、评价、截图、Logo 和量化收益，必须获得明确授权并保留依据。
- 未完成或未验证的接入能力必须标记为规划、评估或演示，不得写成已经交付。

## 每月维护检查

- Demo 数字是否一致。
- 平台名称和接入状态是否准确。
- 官网标题、价格、CTA 与销售材料是否一致。
- 失单原因是否产生新的异议处理或产品判断。
- SEO 内容是否带来有效线索，而不是只有访问量。
- 文档中的负责人、日期、链接和模板是否仍可用。
